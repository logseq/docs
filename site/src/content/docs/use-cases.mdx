Logseq doesn't decide how you organize things — it gives you pages, blocks, tags, and properties, and you build a shape that fits your work. Here are five real shapes people end up with.

Each example below has a **demo graph you can download and import** to poke around in. Graphs that include a PDF come as a `.zip` with the database and its assets folder — import them via File → Import → **SQLite + assets (.zip)**. The rest are a single `.sqlite` file — import via File → Import → **SQLite**.

## Student

Course notes live per lecture, concepts get their own pages, and the journal is the daily log.

- **Tags:** `#Course` (with `instructor`, `semester` properties), `#Lecture`, `#Concept`, `#Assignment`
- **Daily flow:** journal → link today's lecture → take notes under it as nested blocks → drop `#card` on review questions so they become flashcards automatically
- **Why it works:** clicking a concept page (e.g. `[[Mitochondria]]`) shows every lecture and flashcard that ever mentioned it. PDFs of slides sit right in the page for annotation.
- Try it: open the `#Lecture` tag page and you get a table of every lecture with its course.

## Researcher

Papers are first-class objects with metadata, not just names you cite.

- **Tags:** `#Paper` (with `venue`, `authors`, `topic`, `paper-status` properties), `#Project`
- **Daily flow:** import or link the PDF → annotate it inline → write a summary under the paper page → the journal records what you read today
- **Why it works:** the `#Paper` tag page is a filterable table of your whole library — sort by venue, filter to `paper-status: unread`, and your reading list maintains itself.
- Try it: open `Attention Is All You Need` — the paper's notes, the PDF, and its linked references all live on one page.

## Writer

Characters, scenes, and chapters are pages with structure; the draft is an outline.

- **Tags:** `#Character` (with `role`), `#Scene` (with `pov`, `setting`, `scene-status`), `#Chapter`
- **Daily flow:** journal logs word count → draft scenes as nested blocks → `[[Scene name]]` links keep every mention of a character or place reachable
- **Why it works:** opening `#Scene` shows all scenes with their status in a table — you see at a glance what's drafted and what's still an outline. Click a character's page to find every scene they appear in.

## Engineer

Tickets, meetings, and projects share one graph, and the CLI automates the boring parts.

- **Tags:** `#Ticket` (with `ticket-priority`, `area`, `owner`), `#Project`, `#Meeting` (with `sprint`, `attendees`)
- **Daily flow:** standup notes go in the journal → tickets are pages with properties and reproduction steps → sprint meetings link to the tickets they cover
- **Why it works:** the `#Ticket` tag page is a live bug tracker. Code blocks live inside the notes. And the [CLI](/cli) can file a ticket, update its status, or query "all high-priority tickets in payments" from a script or an AI agent via [MCP](/cli/mcp).

## Personal knowledge

Books, movies, recipes, errands — one place for the stuff that's actually yours.

- **Tags:** `#Book` (with `author`, `genre`, `reading-status`, `rating`), `#Movie`, `#Recipe`
- **Daily flow:** journal captures the day in plain language (`Finished [[Exhalation]]`) → tags sort the content into collections automatically → errands are tasks with dates
- **Why it works:** you never organize up front. You write naturally, tag things when it becomes useful, and the tag tables turn into a reading log and watch list you didn't have to build.

## The common pattern

Notice none of these people planned a folder structure. They:

1. Write in the journal or on a page that makes sense that day
2. Tag things when a type emerges (`#Paper`, `#Scene`, `#Ticket`)
3. Let the tag pages and queries do the organizing

That's the workflow Logseq is built around — capture first, structure when it's useful.
